Reporting API: Crash Test

Crash reports are server-side only. Unlike other report types, CrashReport cannot be observed with ReportingObserver — the JavaScript runtime is gone by the time the report is generated. Reports are queued by the browser and POSTed to /report-handler after the tab recovers or you navigate back. Watch the report-server terminal for incoming reports.

  • Firefox supports crash reports since FF130, but this test cannot trigger them. As of FF150 the window.crashReport interface is not supported.
  • The page-unresponsive test works on Chrome only.
  • OOM tests not supported — attempts to allocate memory normally and via WASM are handled without crashing.
  • Address bar crash URLs such as chrome://kill (Chrome) and about:crashcontent (Firefox) do not trigger crash reports.

1. Set crash report context (optional)

window.crashReport lets you attach custom key/value pairs that appear in the crash report body. Call initialize(maxBytes) first (async), then set(key, value) before triggering the crash.


2. Trigger a crash

Warning: The button and address-bar methods below will crash this tab. Keep the report-server terminal visible so you can see the report arrive after you reload.

Via JavaScript

Freezes the main thread. The browser will show a "Page Unresponsive" or similar dialog after several seconds. Kill the tab (not "Stop" or "Wait") to generate the crash report with reason: "unresponsive".

3. What to expect in the server log

After the tab crashes, reload this page (or navigate away and back). The browser will then deliver the queued crash report to the server. Look for something like: 

[
  {
    "age": 5,
    "type": "crash",
    "url": "https://localhost:8443/",
    "user_agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/147.0.0.0 Safari/537.36",
    "body": {
      "crash_report_api": {
        "test-scenario": "unresponsive-trigger"
      },
      "is_top_level": true,
      "reason": "unresponsive",
      "stack": "Website owner has not opted in for JS call stacks in crash reports.",
      "visibility_state": "visible"
    }
  }
]

Crash report delivery can be delayed — the browser batches reports and may not send them immediately on reload. If nothing arrives, wait a few seconds or navigate to another page on the same origin and back.
